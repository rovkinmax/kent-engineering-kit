# Delivery Context

Required:
- `AGENTS.md`, `.kent/project-contract.md`, `.kent/workflow-profile.toml`;
- delivery/report-only authority, current gate evidence and report identities;
- active mapped procedure: `ship-pr.md`, `waiting-pr.md` or `cleanup-task.md`
  under `.kent/commands/`;
- exact branch/HEAD, disposition and resource ownership.

Conditional:
- feedback: affected source/findings; source refresh: README preflight;
- cleanup: process/path and Git/Kent registration proofs;
- packet carriers: exact producer locators and effective transition contract;
- damaged evidence: `contracts/evidence-recovery.md` and exact request;
- R2 acceptance: external locators and installed skill's
  `references/durable-context.md`.

Do not preload disabled CI/Smoke, consumer rollout or installation recipes.
Follow the project contract for evidence and verification ownership. For cleanup,
select the route from native ownership and the outgoing transition contract in
the mapped `cleanup-task.md`, not from Task kind or R2 storage. Only the selected
legacy route's helper exclusively owns final append/seal; retain its blockers in
Task records. Agent-owned cleanup follows the mapped Agent section, including
qualified outside-root storage, genuine producer identity and its own
`cleanup_result`, with necessary work evidence preserved before deletion.
Actual path/Git registration absence proves deletion;
report native registration and branch disposition in the existing native
carrier. No post-delete storage protocol is required. Legacy helper/seal/carrier
obligations do not apply.
