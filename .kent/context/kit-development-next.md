# Kit Source Development Context

This context applies only when the active native Workflow explicitly selects
it. Adding or changing this file does not select a route, declare graph
topology, or activate or replace a Workflow.

## Required

- `AGENTS.md`, `global/AGENTS.md`, `contracts/kit-change-policy.md`, and
  `.kent/project-contract.md`;
- `skills/kent-engineering-kit/references/kit-source-development.md`;
- the exact authorized scope, original human decision when applicable, and
  immutable source baseline;
- only the source, callers, tests, and verification inputs relevant to this
  slice.

When running in a bound Workflow Task, follow that Task's fixed storage
contract and read the applicable
[durable-context reference](../../skills/kent-engineering-kit/references/durable-context.md).
Use the qualified installed `kent-project-memory` storage interface with
genuine native identity, safe private installation/cutover records and the
exact primary R2/Task binding. Do not import a product-local core or require
whole-Kit/profile/helper source parity for ordinary document/MCP operations.
Explicit source inspection/publication stays strict.

An explicitly authorized standalone source slice does not require an invented
Task or a new R2 document write; never fall back to `.todo`. This context
creates no cross-project evidence format. Profile presence and storage access
do not select legacy Plan Contract, ledger, packet, watcher or Janitor routes.

## Scope and ownership

Classify changes using the semantic criteria in the authoritative Kit source
change policy. File paths, diff size, task labels and green checks do not
establish eligibility. Mixed or unknown scope uses the strong route before
implementation.

The source-development instruction describes writer and final-review duties;
the active Workflow and project procedures continue to own exact stage order
and result requirements. Reviewers are independent and read-only; they do not
implement fixes or change scope. If sensitive behavior or out-of-scope work
appears, stop and return it to the authorized scope owner. Do not bundle an
unreviewed scope change with its repair.

## Direct results and review freshness

Use the selected Workflow's declared inputs for the exact reviewed immutable
plan revision/digest, applicable requirements/design references and original
human decisions. Publishing a working document is not acceptance. Preserve
current Script-only adapter acceptance with its trusted PRIMARY selector;
do not substitute a caller-local mapping, the latest working head or an Agent
acceptance bypass. Requirements and original decisions remain authoritative
across source updates.

Follow the active Workflow's declared result contract. Report the actual
candidate under review, checks run and concise findings without fabricating a
pass, reviewer identity or evidence reference. Do not import legacy plans,
packets, ledgers or cleanup protocols unless the active Workflow explicitly
requires them. Do not write an evidence ledger directly.

The independent final reviewer inspects the actual current candidate, relevant
callers, tests and verification configuration, including applicable staged,
unstaged and untracked work. Review must match the candidate that was tested.
After a material source, test, verification-input or scope change, rerun
relevant checks and obtain fresh independent review; never reuse stale PASS
evidence.

## Effects and non-delivery

Source preparation grants no commit, push, PR, merge, publication,
installation, native Workflow activation, Task migration or deletion
authority. Publication, installation, activation and cleanup require their own
effect authority and capable owner. A reviewer reports a cancellation request
or suspected no-delivery condition; the reviewer does not cancel or close a
PR, perform cleanup, or silently change scope.

Cleanup must be explicitly selected and separately qualified for its owner.
Use Script Janitor only for the selected legacy route. An Agent-owned route
needs its own reviewed retention, resource ownership and recovery procedure;
the bounded experiment summarized in
[operations](../../docs/OPERATIONS.md#cleanup-route-qualification)
does not establish production safety or a subprocess-kill guarantee.

An unknown publication or PR outcome remains blocked for settlement. Do not
infer that no effect occurred or route it as successful non-delivery. Never
fabricate a PR, CI result, merge, or cleanup result to satisfy a transition.
