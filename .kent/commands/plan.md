# Plan and Independent Preview Review

Resolve task-fixed storage through the project-memory adapter before choosing
paths. R2 uses protected writes and immutable plan revisions; legacy Tasks
retain their original paths. Missing local caches do not disprove acceptance.
Before repeating a decision, inspect Plan Contract evidence, ledger references
and the original human message or Question answer, including supersession.

1. Inspect the selected managed root and relevant behavior. Preserve
   `fixed_point` separately from the moving integration target.
2. Prepare one bounded preview naming files, graph delta, rollout, rollback
   and restart impact. Cite exact human sources for any scope supersession.
   Establish the requested endpoint, capable delivery/adoption owners,
   available interfaces, effect guards and completion evidence read-only.
   Keep writer steps separate from downstream reviews, runtime and delivery.
3. Freeze the preview and compute SHA-256. Obtain one independent read-only
   review inside Plan from an existing callable `architecture-designer` or
   `researcher` leaf. Bind its identity, verdict and findings to that hash.
   Optional grill critique is useful for unresolved decisions; it is not an
   extra universal prerequisite or a substitute for an independent review.
4. After resolving findings, send the same preview/hash and first PASS receipt
   to the separate Plan Review node for the second independent read-only review.
5. Only after both same-hash PASS receipts may `plan_review_accept` request
   explicit human approval. Preserve actual approval and both receipts in
   discoverable existing Task evidence; a pending request is not acceptance.

Revalidation refreshes both reviews and human approval for substantive plan
changes. Task-scoped corrections and missing agent bookkeeping do not create
new product decisions. Recover bounded missing evidence without inventing old
reviews or consent. Keep original preview ScopeHash distinct from a normalized
plan digest and reference the one authoritative preview instead of copying it.

Working plans are ordinary project documents, not portfolio operation JSON.
Compact them with immutable-history references while preserving every actual
human constraint. Use the declared adapter framing and preflight full request
bytes. Do not impose exact test-set equality or waive accepted capture/reset
or tooling limits.

For explicit report-only qualification, `plan_path=not-applicable` is valid.
Retain preview/reviews/approval in Task records or ignored
`build/kent-workflow/<task>/`, never as unknown restricted runtime files.
Do not manufacture a tracked plan.

Use generated transition carriers and existing evidence commands. User-facing
decisions are concise Russian; repository artifacts are English. Source approval
does not authorize Git publication, live workflow, installation or consumer
effects. Preserve the requested endpoint and accepted effect-specific authority
without repeated stage permissions; new scope, risk or independent judgment
still requires a decision.

When a declared route carries `delivery_context`, preserve its exact supported
v1/v2 packet; do not put transport state in the plan digest or infer
`pr_base_branch`. For compaction or workflow-reset lock refresh, follow
`global/AGENTS.md`: verify the native compaction event and refreshed lock;
the Session ID may remain unchanged, and source publication alone does not
refresh an existing Session's locked instructions.

Record actual delivery identities/results in progress evidence, not by
rewriting the frozen preview. Installed acceptance requires installed-byte
readback and fresh instruction loading; source tests or a merged PR alone
cannot establish it. Existing Sessions retain locked instructions.
