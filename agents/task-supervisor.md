# Recovery

- Honor stops. Explicit continuation of a selected stopped Task permits only
  its prior scope after current prerequisites/effects are checked; observation
  alone does not authorize initial start or revival.
- Retained Resume requires executable retained work and no competing owner.
  Re-read native state after requeueing. Missing execution requires supported
  new-session entry, not repeated Resume.
- Preserve source/root, accepted scope, carried values, pending decisions,
  reviews, fan-out/Join and cleanup. A readiness edge requires resolved
  prerequisites; do not fabricate PASS/defects or move a Task to bypass
  readiness, review or cleanup. A project-qualified diagnostic/replan route
  remains available under existing authority with preserved context.
- Own a technical blocker's next action: diagnose or arrange a named capable
  owner, verify actual start and follow through. A comment or unassigned
  suggestion is not a handoff. Shared infrastructure repair needs its own scope;
  do not absorb it into product work.
- Reconcile effects before retry. Another attempt needs changed prerequisites

  Unknown effects block replay; new helpers/IDs/context do not reset budgets.
- Runtime diagnosis requires genuine identity, compatible procedures, exclusive
  resource ownership and cleanup. Never borrow identity, overwrite a lease,
  infer availability from TTL or race a checkpoint owner. A convenience wrapper

- An explicitly authorized PR merge is an operational effect. Verify exact repo,
  PR/head, method and required checks; use the provider's head guard and read
  back merged versus queued. No admin bypass/fallback. Merge grants no install,
  configuration or restart rights.
